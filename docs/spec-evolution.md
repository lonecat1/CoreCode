# 自进化记忆沉淀

## 目标

把一次执行留下的原始轨迹，转化为以后可以复用的记忆资产，并让这些资产在
相似任务或同类错误再次出现时自动回到模型上下文。闭环是：

```
执行
  → 反思（发生了什么、是否成功、怎么恢复）
  → 提炼（情景 / 程序 / 修复 / 画像）
  → 分类持久化（项目库 / 全局画像库）
  → 增量索引（BM25 倒排索引）
  → 按需复用（任务开始与工具报错后的下一步）
  → Skill 生长（重复成功的程序记忆物化为 SKILL.md）
```

实现不增加运行时依赖，也不额外调用模型：反思与提炼是确定性的，因此离线
mock 模式、CI 与无 API 环境都能跑通。

## 资产分类

| 类型 | 来源 | 典型内容 | 作用域 |
|---|---|---|---|
| `episodic` | 一个回合的请求、工具动作、错误与结果 | 「这次任务是怎么完成/失败的」 | 项目 |
| `procedural` | 成功工具调用的有序序列 | 「哪套操作步骤验证有效」 | 项目 |
| `repair` | 工具错误之后出现成功操作 | 「这个错误当时是怎么修好的」 | 项目 |
| `profile` | 用户明确的长期偏好、约束、身份表达 | 「以后始终用中文」「call me …」 | 全局 |
| `skill` | 出现至少 2 次的程序性记忆 | 可被 `load_skill` 使用的受管工作流 | 项目 |

资产字段包含 `title/content/tags/confidence/importance/occurrences/evidence`、
来源会话、创建/更新时间、访问次数和去重键。`dedupe_key` 是合并同类经验的主键：

- 程序经验按「工具 + 稳定动作特征」组合，临时绝对路径不进入键；
- 修复经验按「失败工具 + 规范化错误签名 + 恢复动作」组合；
- 用户画像按规范化原句去重；
- 情景记忆按会话、用户消息 id、请求与结局去重；
- Skill 与程序经验一一对应。

## 持久化

根目录由 `CORECODE_HOME` 决定：

```
<CORECODE_HOME>/evolved-memory/
  global/
    assets.json
    index.json
  projects/<项目名-路径摘要>/
    assets.json
    index.json
```

`assets.json` 是事实来源；`index.json` 是派生索引。两者 id 集合不一致时，
启动会从资产重建索引。写入采用同目录临时文件 + `os.replace`，避免半份 JSON。

自动生长的 Skill 写到项目内：

```
<cwd>/.corecode/skills/evolved-<稳定摘要>/SKILL.md
```

文件内带 `managed-by: corecode-self-evolution` 标记；没有标记的同名文件不会被
覆盖。

## 反思与提炼规则

`evolution/reflect.py` 先构造 `TurnReflection`，再产出资产：

1. 从工具调用与结果按 `toolUseId` 配对，保留错误标志与执行顺序。
2. 记录成功调用、失败调用、最终答复、结局与恢复步骤。
3. 对用户输入做敏感值脱敏，并从明确的长期表达中提炼画像。
4. 有至少两个有意义成功步骤时，生成程序性记忆。
5. 错误后出现后续成功步骤时，生成修复记忆。
6. 每个非挂起回合生成一条情景记忆；`awaiting_user` 与中途取消不沉淀。

配置新凭据、密码、Bearer token 等常见形式会在入库前替换为 `[REDACTED]`。

## 索引与检索

索引是零依赖 BM25 倒排索引。英文路径/命令按词切分；中文按字符二元组切分，
不依赖分词词典。写入资产时只更新该文档的 posting，不重建全库。

每次模型调用前，宿主从最近消息构造检索查询并注入模型可见的 system 投影：

- 最近用户请求；
- 最近的工具调用；
- 最近工具结果，尤其是 `isError=true` 的错误文本。

检索结果受以下约束：

- 最多 7 条资产；
- 各类别有独立配额，避免情景记忆挤掉修复经验；
- 最多约 6,500 字符；
- 错误存在时修复资产加权；
- 最高重要度的用户画像可以常驻，不依赖词面完全匹配；
- 记忆正文中的 `<`/`>` 会被转义，避免伪造 `<evolved_memory>` 边界。

注入只改变模型可见投影，不写回真实会话；召回统计在回合结束时一次性落盘。

## 错误修复加速

工具报错后，下一次模型调用读取到的是更新后的消息序列。检索查询包含错误
签名，因此同一错误的历史修复资产会在模型决定下一步之前出现。修复资产同时
保留失败输入与恢复步骤，模型可以据此调整命令、补充前置动作或换工具。

## Skill 生长

同一程序签名第二次出现后：

1. 生成确定性 `evolved-<摘要>` 名称；
2. 从程序记忆的步骤、验证结果和示例生成 `SKILL.md`；
3. 写入项目 Skill 目录；
4. 保存 `skill` 资产并更新索引；
5. 宿主刷新 Skill 目录与系统提示，使当前会话后续步骤即可使用。

Skill 只记录已验证的流程，不会把失败轨迹直接固化为技能。

## 可观察性

`/memory` 在原有静态指令文件报告后追加：

- 资产总数与五类计数；
- 项目库、全局库、受管 Skill 路径；
- 最高重要度资产列表。

`SessionHost.last_reflection_error` 与 `last_memory_error` 分别保存最近的沉淀、
召回异常；任一阶段失败都不会中断或回滚已经完成的回合。

## 测试

`tests/test_evolution.py` 覆盖：

- 四类资产同时提炼；
- 凭据脱敏；
- 资产跨引擎实例持久化与索引落盘；
- 中文错误检索；
- 同类错误出现时自动注入修复记忆；
- 用户画像跨项目复用、项目记忆不串库；
- 重复流程合并、第二次出现后生成受管 Skill；
- `agent_loop` 的记忆上下文挂载点；
- `SessionHost` 回合后自动沉淀与跨会话召回。
